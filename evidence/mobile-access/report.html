Authentication boundary

Independent check | Observed result

Anonymous requests to 16 private surfaces | 401 for APIs, crops, tiles, export, app assets, evidence and API documentation. Forged identity/proxy headers do not authorize access.

Cryptographic identity verification | Generated test RSA keys and signed tokens run through Google's actual verifier. Only the certificate HTTP response is substituted. Wrong signature, audience, issuer, expiry, future issue time and nonce are rejected.

Allowed account and sessions | Approved, verified identity enters; another account cannot. Opaque session hashes persist across restarts. Expiry, removed allowlist access and logout invalidate access.

Write and login protection | Cross-origin writes, missing CSRF tokens, reused/expired login challenges and excessive sign-in attempts are rejected. Cookies are Secure, HttpOnly and SameSite=Lax.

Missing configuration and local listener | The actual public CLI refuses to start with the current incomplete config. Local listener rejects forwarded proxy requests. The public replica does not reset the local OSM worker's running requests.

Historical state | Exact row hashes match the frozen pre-change database for algorithms, tiles, jobs, attempts, findings, reviews and readings. 116 tiles and 14,525 historical finding rows retained. Active worker still reports 696 completed runs.

Corrections and limits

The first auth run exposed invalid issuer errors being reported as temporary verification failures. Both refused access; the exception handling now returns the appropriate identity rejection. A test setup also referenced a nonexistent OSM helper; it was corrected to use the real request API.

Phone inspection caught status text overlapping attribution. Attribution now sits above status. Small-screen open filters are bounded and scrollable. Landscape retains both workflow tabs.

These are browser viewport checks, not physical iOS/Android testing. Google popup behavior, account controls after a real login, external HTTPS, tunnel continuity and cellular access remain unverified.

No detection algorithms, confidence claims, name suggestions, historical-coordinate correction, or developed-area policy changed.
