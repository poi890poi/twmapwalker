Pinch zoom fixed. Individual features easier to reach.

29 September 2026 · Actual public-site screenshots at 390 × 844 CSS pixels.

What was blocking the map?

The large message was internal validation JSON. During a pinch gesture, Leaflet can report a temporary fractional zoom. The screenshot supplied 15.218098151851985, while the server expected integer zoom and display_zoom. A direct request reproduced HTTP 422. The viewer then printed that entire error array over the map.

The browser now rounds request zoom and defers refreshing during motion. The server also accepts valid fractional view zoom, rounding half-up, so already-open pages can recover. The exact reported request now returns HTTP 200. Tests confirm fractional and corresponding integer requests select identical map/list/export results. Invalid and out-of-range zooms still fail.

Future errors use short readable messages with a dismiss button. Messages also disappear on map movement or after six seconds. The compact-message screenshot below uses the normal Copy view link notification; raw-error sanitization was tested separately without injecting an error into the live page.

Verification and limits

105 Python tests pass. Node regressions cover zoom normalization and readable errors; JavaScript syntax checks pass. Browser checks verify before/after grouping, one-tap expansion, opened source evidence, automatic message expiry and manual dismissal.

The available browser control does not emulate physical multitouch. The exact reported fractional value was instead tested through the live HTTP endpoint and across API selection/export regressions. A real phone pinch still needs user verification after reload.

Detector code and algorithm registry are unchanged. Existing background work was briefly paused to finish its active tile, safely restarted, then resumed with its queue intact. Those existing jobs continue adding detections, so whole-database byte equality is not claimed.

These are viewer fixes. Display selection, raw detections, trail deferral, authentication and tile-cache behavior are unchanged. No detection-accuracy claim.
