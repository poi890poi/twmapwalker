Verification and boundaries

97 tests passed. Existing Google verification tests remain, with added code login, wrong-code, nonce/CSRF, expiry, rotation, logout, rate-limit and fail-closed configuration tests.

Seven independent public HTTPS requests to APIs, export, app assets, evidence and tiles were rejected without a session.

Browser sign-in used the real configured code. Logout returned to the sign-in page. The 320 px signed-in account menu and sign-out control fit without horizontal overflow.

All historical table row hashes match the pre-deployment baseline: algorithms, tiles, jobs, attempts, findings, readings and reviews. No detection changes or second GPU worker.

Code sessions last at most eight hours and never exceed code expiry. Rotation revokes existing sessions after the public service restarts. Code possession grants access; this mode does not verify an email address.

Limitations and negative evidence

The first replay test observed 403 because successful login had correctly deleted the challenge cookie. The test was strengthened to restore that cookie and replay the consumed nonce; the server rejected it with 401. One browser attempt to navigate directly to a protected API after logout was blocked by the browser itself; it is not counted as a successful API verification. The separate HTTPS checks supply that evidence.

Physical cellular-phone access and Google account sign-in remain untested. Google can replace code mode after an OAuth client is registered. Cloudflare Quick Tunnel supplies a temporary address with no uptime guarantee; see Cloudflare's documentation.
